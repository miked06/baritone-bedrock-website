Preview and build schematics in Minecraft Bedrock

Updated November 7, 2026 · Maintained by miked06

Baritone Bedrock includes a built-in schematic workspace: load a structure, inspect its wireframe differences, move or rotate the placement, then start automatic construction. This provides a Bedrock alternative for the preview-and-build workflow associated with Java Schematica or Litematica; it does not install those Java mods.

Supported schematic formats

FormatUseImportant limit
.mcstructureBedrock import and exportExport covers blocks and supported state types.
.schemSponge importJava-to-Bedrock block/state mappings can differ.
.schematicLegacy importLegacy variants can need manual inspection.
.litematicLitematica file importFile support is not the Java mod or its full renderer.

Load a preview, then build

Put the file in %LOCALAPPDATA%\BaritoneBedrock\schematics\. Quote paths containing spaces. Choose a clear placement in your world:

#schematic load "house.mcstructure" 100 64 100
#schematic rotate 90
#schematic requirements
#schematic verify
#schematic build
#stop

Wait for loading and comparison results. Cyan marks missing blocks, red marks wrong blocks, orange marks removals and gray marks unloaded positions. Matching blocks are hidden. This in-game preview uses bounded outlines. It does not render textured ghost blocks inside Minecraft.

Export a local textured 3D preview

#preview3d "C:\exports\house-preview.html"

Open the exported HTML in a WebGL browser and select an unpacked Bedrock resource-pack folder with its block and texture definitions. The viewer supports orbit, layers and opacity, with supported cube, slab, stair and log orientations. Files stay local; textures are not bundled or uploaded. Complex/connected shapes use placeholders and transparency is approximate.

Manual guidance, foundations and recovery

#assist on
#assist status
#technical
#assist off
#construction plan temporary cobblestone 16
#construction start temporary cobblestone 16
#construction recover

The manual assistant highlights a nearby supported missing block and selects matching hotbar material. You move and click. #technical flags components and states needing manual checks; it does not simulate redstone circuits.

Construction planning adds temporary supports or permanent foundations, builds the structure and conditionally cleans up temporary columns. Use loaded dry ground within the selected depth, and inspect the plan before starting. #construction recover is for an interrupted saved job, not a command to run after a completed build. It checks the same world/dimension, loaded cells and current protection before repeating the saved phase. It is not a world backup or inventory rollback.

Materials, verification and repair

#schematic requirements allocates inventory against estimated materials, including supported doors, beds and double slabs. Unloaded positions are unknown. #schematic verify compares loaded blocks and supported orientation behavior; it does not certify arbitrary state/NBT equivalence. After inspecting the results, #schematic repair builds differences while respecting settings and protection.

Save placements and export a Bedrock structure

#schematic store house
#schematic placements
#schematic use house
#sel pos1 100 64 100
#sel pos2 110 74 110
#export house-copy.mcstructure

Saved placements retain source paths, origin, rotation, mirror and layer settings. Up to eight remain resident; up to 64 presets persist per world/dimension. Export refuses unknown chunks and existing files. It does not include entities, container contents, block-entity data or secondary waterlogged fluid layers.

Validation and edition differences

Review Java imports before building. Full native construction recovery and other new module combinations still need gameplay validation on Minecraft 26.63. See the 1.7.0 status matrix, format documentation and Java and Bedrock comparison.
