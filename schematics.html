Preview and build schematics in Minecraft Bedrock

Updated November 1, 2026 · Maintained by miked06

Baritone Bedrock includes a built-in schematic workspace: load a structure, inspect its wireframe differences, move or rotate the placement, then start automatic construction. This provides a Bedrock alternative for the preview-and-build workflow associated with Java Schematica or Litematica; it does not install those Java mods.

Supported schematic formats

FormatUseImportant limit
.mcstructureBedrock import and exportExport covers blocks and supported state types.
.schemSponge schematic importJava-to-Bedrock block/state mappings can differ.
.schematicLegacy schematic importLegacy variants may need manual inspection.
.litematicLitematica file importFile support is not the Java mod or its full renderer.

Load a preview, then build

Put the file in %LOCALAPPDATA%\BaritoneBedrock\schematics\. Use quotes around filenames containing spaces. The coordinates below are an example; choose a clear area in your world.

#schematic load "house.mcstructure" 100 64 100
#schematic rotate 90
#schematic requirements
#schematic verify
#schematic build
#stop

Wait for loading and comparison results before building. Cyan marks missing blocks, red marks wrong blocks, orange marks blocks to remove and gray marks unloaded positions. Matching blocks are hidden. The preview uses bounded difference boxes, rather than textured ghost blocks.

Materials, verification and repair

#schematic requirements allocates available inventory against estimated materials, including supported doors, beds and double slabs. Unloaded positions are unknown and excluded from the estimate. #schematic verify compares live loaded blocks. After inspecting the results, #schematic repair starts the difference builder, respecting build settings and protected areas.

Save placements and export a Bedrock structure

#schematic store house
#schematic placements
#schematic use house
#sel pos1 100 64 100
#sel pos2 110 74 110
#export house-copy.mcstructure

Saved placements retain the source path, origin, rotation, mirror and layer settings. Up to eight stored placements remain resident; up to 64 presets persist per world/dimension. Export refuses unknown chunks and existing destination files.

What does not transfer between editions?

Not every Java block/state has an identical Bedrock representation. Export does not include entities, container contents, block-entity data or secondary waterlogged fluid layers. Review an imported preview before building and read the format documentation and module limits.
