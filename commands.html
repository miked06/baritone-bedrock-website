Baritone Bedrock commands

Updated November 7, 2026 · Maintained by miked06

Baritone Bedrock commands start with # in Minecraft chat. They are handled locally by the injected DLL. Start with #help; use #help command for detailed syntax and #stop to stop current activity.

Navigation, mining and building examples

CommandPurpose
#goto 100 64 100Walk toward coordinates in your world.
#mine 32 diamondStart mining toward a total inventory quantity.
#schematic load house.mcstructureLoad a preview before construction.
#schematic requirementsCompare estimated materials with inventory.
#schematic buildBuild the current placement.
#doctorInspect compatibility prerequisites.
#whyInspect recent task failures.
#stop / #unloadStop activity or unload the DLL.

Storage, loadouts and restocking

#storage add supplies 100 64 100
#storage scan all
#storage find cobblestone
#restock item cobblestone 64 supplies
#loadout fill mining supplies

Register real supported containers and create a loadout before filling it. Restock quantities are total inventory targets. Transfers use normal game requests and observed results. Compatible plain piles can merge; unknown/custom metadata needs empty destinations. Active loadout minimums protect deposits.

Production objectives and recipes

#storage add table 102 64 100
#storage add output 104 64 100
#craft plan torch 16
#produce table torch 16 supplies output
#produce status

#produce requests additional output. It makes a fresh dependency plan, can fetch supplies, gather supported base resources, craft intermediates and optionally deliver the result. Unsupported missing inputs stop the job. It does not turn raw ores into ingots automatically or invent ingredients.

The starter planner has 18 output recipes. The repository's tools/import_recipes.py can import supported local Bedrock recipe descriptions into a catalog of up to 2048 outputs; Minecraft still decides unlocks and recipe validity. Read the production limits before choosing a target.

Multi-furnace workshop

#storage add furnace_a 106 64 100
#storage add furnace_b 108 64 100
#workshop start raw_iron iron_ingot 32 coal 4 furnace_a furnace_b
#workshop status

Use registered empty stations and keep the required input/fuel in inventory. The example splits 32 input items and an explicit budget of four coal between two stations. The pool loads stations before collection passes, checks receipts and expected output, and returns unused fuel. Only supported one-to-one recipes are handled; recipe/fuel suitability remains the game's decision. Inspect stations after interruption.

Targeted crop harvesting

#harvest sugar_cane 64 16
#harvest bamboo 64 16
#harvest cactus 32 16
#harvest pumpkin 16 16
#harvest melon 64 16

Quantities are additional output; melon counts slices. The final number is the radius, from 1 to 64 blocks. Base stems are preserved, and a current selection restricts harvesting. Generic #farm remains available for mixed crops and replanting. Jobs require observed item quantities to finish.

Map and road planning

Open Map in the Windows control panel to inspect loaded and session-visited chunks, nearby markers, the route and protected-area footprints. Select a destination, then choose Go to selection. This map does not show surface heights or every persistent cached chunk.

#road 100 63 100 140 65 110 3 cobblestone 8
#schematic requirements
#construction plan permanent cobblestone 16

This creates an inspectable road preview and a foundation plan. Coordinates describe paving blocks, not player feet. Roads go along X then Z with bounded width, grade, lighting and volume. Building requires a separate construction start; inspect removals, resources and support limits first.

Workflow templates and local diagnostics

#workflow templates
#workflow template produce-store table torch 16 supplies output
#workflow list
#workflow run
#workflow pause
#report "C:\exports\baritone-report.zip"

Templates load paused. Inventory-sensitive nodes retain absolute targets for recovery in the same world/dimension. Other templates cover build preparation, mining/storage, loadouts and harvesting. The visual editor can edit conditions and failure branches. Diagnostic ZIP export is local; inspect world names, coordinates and file paths before sharing.

Validation and complete reference

These examples describe implemented commands, not proof that every native combination has been exercised on Minecraft 26.63. See the 1.7.0 validation matrix, 1.6 expansion guide and complete command reference. Use #help command for current syntax.
